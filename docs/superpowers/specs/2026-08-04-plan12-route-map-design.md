# Plan 12 — 여행 경로 맵

날짜: 2026-08-04

## 배경

Plan 11에서 일정 탭이 들어가면서 "언제 어디를 갔는지"가 처음으로 앱 안에 쌓이기 시작했다. 그런데 그 데이터는 날짜별로 흩어져 있어서, 여행 전체를 하나의 여정으로 되돌아볼 자리가 없다.

원 요청은 이렇다 — "단순화된 지도 상에 여행 기간 내 어디어디 거쳐 갔는지 디자인적인 단순한 경유 지도".

## 목표

- 여행에서 거쳐 간 장소를 방문 순서대로 잇는 시각화를 리포트에 넣는다.
- 장소는 일정의 `placeName`을 기본으로 하고, 경비 중 사용자가 경유지로 표시한 것을 더한다.
- 여행이 끝난 뒤에도 경유지를 표시하고 해제할 수 있다.

## 비목표

**실제 지리 좌표를 쓰지 않는다.** 이 앱에는 좌표가 어디에도 없다. 얻으려면 장소검색 API 키와 프록시 함수가 필요한데(Plan 11에서 같은 이유로 지도 SDK 임베드를 덜어냈다), 얻는 것은 "노드 위치가 실제 방위와 맞는다" 뿐이다. 이 시각화의 목적은 길찾기가 아니라 회고다. **노드 위치는 방문 순서만 나타내며 방위·거리와 무관하다.**

그 밖에 이번 범위가 아닌 것:

- 노드 클릭 상호작용. 거기서 무엇을 했는지는 일정 탭이 답한다.
- 이동 수단·소요 시간 표시.
- 경로 맵의 이미지 내보내기/공유.
- 공개 리포트 URL 노출 (§1.3 참조 — 애초에 공개가 아니다).

## 1. 데이터

### 1.1 경비의 `isWaypoint`

`trips/{tripId}/expenses/{id}` 에 필드를 하나 추가한다.

```js
isWaypoint: false   // 기본값
```

기존 문서에는 이 필드가 없다. 읽는 쪽에서 `=== true` 로 비교하므로 `undefined`는 자연히 거짓이고, **마이그레이션이 필요 없다.**

### 1.2 `setExpenseWaypoint` — 왜 별도 콜러블인가

`updateExpense`에 얹지 않는다. 그 함수는 멤버에게 **본인이 입력한 것만, 확정 전에만** 수정을 허용한다(`expenses.js`의 `enteredBy !== session.memberId → FORBIDDEN`, `expense.confirmed → EXPENSE_LOCKED`).

경로 맵을 만드는 시점은 대개 여행이 끝난 뒤 — 경비가 전부 확정된 뒤다. 그 규칙을 물려받으면 정작 필요할 때 아무것도 표시할 수 없다.

따라서 새 콜러블을 둔다.

| 항목 | 값 | 근거 |
|---|---|---|
| 권한 | `['admin', 'member']` | 경로 맵은 공동의 기록이다 |
| 소유자 제한 | **없음** | 남이 입력한 경비도 경유지로 표시할 수 있어야 한다 |
| 확정 잠금 | **없음** | 확정 후가 이 기능의 주 사용 시점이다 |
| `requireTripEditable` | **걸지 않는다** | 완료된 여행의 회고가 주 사용 시점이다 |

선례가 있다: `setMemberSettled`와 `setMyAccount`도 `requireTripEditable`을 걸지 않는다. 돈을 바꾸는 행위가 아니라 기록을 정리하는 행위라서다. 경유지 표시도 같은 성격이다.

```
setExpenseWaypoint(db, { sessionToken, tripId, expenseId, isWaypoint }) => { ok: true }
```

검증: `expenseId`가 실재해야 하고(`EXPENSE_NOT_FOUND`), `isWaypoint`는 불린으로 강제 변환한다.

### 1.3 프론트가 데이터를 얻는 방법

리포트에서 `getReportData`와 `listSchedules`를 **병렬로** 호출한다.

`getReportData`를 확장하지 않는다. 정산 계산이 걸린 함수이고 백엔드 테스트가 두껍게 붙어 있는데, 시각화 하나 때문에 반환 형태를 바꿀 이유가 없다. `Promise.all`이므로 왕복이 둘이어도 체감 지연은 하나일 때와 같다.

**노출 범위 확인**: `getReportData`와 `listSchedules` 둘 다 `requireSession(db, token, ['admin','member'], tripId)`을 요구한다. `/t/{slug}/report` 경로는 클라이언트에서 세션을 검사하지 않지만 데이터 호출이 실패하므로, 장소 이름이 인증 없이 새지 않는다.

### 1.4 경유지가 만들어지는 규칙

| 출처 | 포함 조건 | 정렬 키 |
|---|---|---|
| 일정 | `placeName`이 비어있지 않고 `date`가 있음 | `date`, 그다음 `startMin` |
| 경비 | `isWaypoint === true`이고 `date`가 있음 | `date`, 그다음 `1440` (그 날의 맨 뒤) |

경비에는 시간 정보가 없다. 정렬 키를 `1440`으로 고정해 **그 날의 일정 뒤에 놓는다** — 임의의 규칙이지만 명시적이고, 하루 안에서 순서가 뒤집히는 비결정성이 없다.

`date`가 없는 일정(날짜 미정)은 여정에서 자리를 가질 수 없으므로 제외한다.

**연속 중복은 접는다.** 정렬된 목록에서 바로 앞 노드와 `placeName`이 같으면 새 노드를 만들지 않는다. 같은 편의점에서 경비 3건을 찍어도 노드는 하나다.

**날짜가 다르면 접지 않는다.** 제주공항이 첫날과 마지막 날에 나오면 노드가 둘이어야 "돌아왔다"가 보인다. 따라서 접기 판정은 `placeName`과 `date`를 함께 본다.

**`placeName`이 URL인 경우**(Plan 11에서 지도 링크 붙여넣기를 허용했다) 라벨로 쓸 수 없다. `^https?://`이면 해당 일정을 경유지에서 제외한다 — URL을 노드 이름으로 찍는 것보다 낫다.

## 2. 레이아웃

### 2.1 지그재그 배치

한 행에 **3개 고정**, 행마다 방향이 뒤집힌다. 0행은 좌→우, 1행은 우→좌.

```
   ①────────②────────③
                      │
   ⑥────────⑤────────④
   │
   ⑦────────⑧────────⑨
```

**행당 개수를 뷰포트에 따라 바꾸지 않는다.** SVG를 `viewBox`로 그리고 `width:100%`로 두면 폰에서는 셀이 작아지고 데스크탑에서는 커진다. 반응형 분기가 사라지고, 순수 함수가 뷰포트 폭을 알 필요도 없어진다.

장소가 늘면 행이 아래로 추가된다. **고정 높이 박스에 우겨넣지 않으므로 개수 상한이 필요 없다.**

### 2.2 좌표

`viewBox`는 `0 0 300 H` 좌표계다.

| 값 | 크기 |
|---|---|
| 셀 폭 | 100 |
| 행 높이 | 90 |
| 노드 반지름 | 14 |
| 좌우 여백 | 셀 안에서 중앙 정렬 (cx = 50, 150, 250) |

`H = rows * 90 + 20`. 행 인덱스 `r`, 행 안 위치 `c`에 대해:

```
cx = 50 + (r % 2 === 0 ? c : 2 - c) * 100
cy = 45 + r * 90
```

### 2.3 연결선

- **같은 행**: 인접한 두 원의 가장자리를 잇는 직선.
- **행이 바뀔 때**: 행이 끝나는 쪽에서 아래로 도는 곡선. 3차 베지어 한 개로 그린다. 마지막 노드 아래에서 시작해 다음 행 첫 노드 위로 들어간다.

선 색은 중립 회색(`--rule` 계열), 굵기 2.

### 2.4 라벨

이름이 셀 폭(100)을 넘는다. SVG에는 자동 줄바꿈이 없다.

**7자씩 최대 두 줄로 쪼개고, 넘치면 두 번째 줄 끝에 `…`를 붙인다.** 즉 14자까지 온전히 보이고 그 이상은 잘린다. 전체 이름은 `<title>` 자식 요소에 넣어 데스크탑에서 툴팁으로 뜨게 한다.

`<title>`은 터치 환경에서 뜨지 않는다. 이는 감수한다 — 전체 이름이 꼭 필요하면 일정 탭에 있다.

### 2.5 날짜 칩

**앞 노드와 `date`가 다른 노드에는 작은 날짜 칩을 붙인다** (`8/11` 형식, 기존 `formatDate` 재사용). 원 위쪽에 놓는다.

지그재그 배치는 날짜 경계를 잃어버린다. 이 칩 하나로 "며칠째 어디"가 읽히고, 비용은 텍스트 한 줄이다.

### 2.6 색

노드 채움은 카테고리 색(`categories.js`의 `CATEGORY_META.mark`)을 쓴다. 새 팔레트를 만들지 않는다 — 기존 값은 색각이상 검증(인접쌍 CVD ΔE 9.1)을 통과한 것이고, 리포트의 도넛 차트·태그와 색이 일치해야 같은 시스템으로 읽힌다.

번호는 원 안에 흰색으로, 이름은 원 아래에 본문색으로.

### 2.7 머리말

시각화 위에 한 줄:

```
8/10 – 8/13 · 7곳 · 제주
```

기간, 경유지 수, `trip.location`. 값이 없는 항목은 생략한다.

### 2.8 빈 상태

경유지가 하나도 없으면 SVG를 그리지 않고 안내를 낸다.

```
아직 경로에 표시할 장소가 없습니다.
일정에 위치를 적거나, 경비 목록에서 경유지로 표시해보세요.
```

무엇을 해야 채워지는지 말해준다 — 두 경로 다 사용자에게 안 보이는 기능이라 안내가 없으면 빈 화면의 이유를 알 수 없다.

## 3. 경유지 토글 UI

**경비 카드에 직접 붙는 토글이다. 경비 수정 모달에 넣지 않는다.**

수정 모달은 본인 것·미확정만 열린다. §1.2에서 콜러블 권한을 일부러 느슨하게 잡았는데, UI를 모달에 두면 그 제약이 UI 층에서 그대로 되살아나 설계가 무의미해진다.

- 위치: 경비 카드의 액션 영역. 멤버 뷰(`경비목록`)와 관리자 뷰(`경비확인`) 양쪽.
- 형태: 눌린 상태가 보이는 작은 버튼. `📍 경유지` / 표시되면 강조.
- **남의 경비, 확정된 경비에서도 눌린다.**
- 낙관적 갱신은 하지 않는다. 호출 성공 후 상태를 반영한다 — 실패했는데 켜진 것처럼 보이면 경로 맵과 어긋난다.

### 4.1 `routeMap.js`의 인터페이스

세 함수는 파이프라인이다. 각각 따로 테스트된다.

```js
// 일정 + 경비 → 순서대로 정렬되고 중복이 접힌 경유지 목록
buildWaypoints(schedules, expenses)
  => [{ label, category, date }]

// 경유지 목록 → 좌표가 붙은 노드 + 캔버스 높이
serpentineLayout(waypoints)
  => { nodes: [{ waypoint, index, row, col, cx, cy }], width: 300, height }

// 경유지 목록 → 완성된 SVG 문자열 (내부에서 serpentineLayout을 호출)
renderRouteMap(waypoints, { location, period })
  => string
```

`renderRouteMap`이 `serpentineLayout`을 안에서 부르므로 `report.js`는 `buildWaypoints` → `renderRouteMap` 두 단계만 쓴다. `serpentineLayout`을 따로 export하는 이유는 좌표 계산을 렌더링과 분리해 테스트하기 위해서다.

**에러 코드**: `setExpenseWaypoint`는 `EXPENSE_NOT_FOUND`(이미 있음)와 세션 관련 코드만 던진다. **새 코드는 필요 없으므로 `errorMessages.js`와 `httpsErrors.js` 둘 다 손대지 않는다.**

> Plan 11의 교훈: 새 에러 코드를 도입한다면 `public/errorMessages.js`의 `MESSAGES`와 `functions/src/lib/httpsErrors.js`의 `DOMAIN_ERROR_CODES` **두 곳 모두**에 등록해야 한다. 하나만 하면 `toHttpsError`가 코드를 버그로 간주해 `INTERNAL_ERROR`로 바꿔 내보내고, 한국어 문구가 사용자에게 도달하지 못한다. 이번 범위에서는 신규 코드가 없으므로 해당 없음.

## 5. 테스트

### `public/test/routeMap.test.js` (신규, `node --test`)

`buildWaypoints`:
- 일정은 `date` → `startMin` 순으로 정렬된다
- 경비는 같은 날 일정들 뒤에 온다
- `placeName`이 빈 일정은 제외된다
- `date`가 없는 일정은 제외된다
- `isWaypoint`가 아닌 경비는 제외된다
- `isWaypoint`가 `undefined`인 기존 문서는 제외된다 (마이그레이션 불필요를 고정)
- `placeName`이 `https://`로 시작하면 제외된다
- 같은 날 연속으로 같은 장소면 노드 하나로 접힌다
- 날짜가 다르면 같은 장소라도 노드가 둘이다
- 사이에 다른 장소가 끼면 접지 않는다 (A, B, A → 노드 셋)

`serpentineLayout`:
- 0행은 좌→우, 1행은 우→좌
- 4번째 노드는 1행의 오른쪽 끝(cx 250)에 온다
- 7번째 노드는 2행의 왼쪽 끝(cx 50)에 온다
- 총 높이가 행 수에 비례한다
- 노드 0개면 빈 배열

`renderRouteMap`:
- 장소명이 이스케이프된다
- 14자를 넘으면 잘리고 `…`가 붙는다
- 전체 이름이 `<title>`에 들어간다
- 날짜가 바뀌는 노드에만 날짜 칩이 있다
- 노드 채움색이 카테고리 색과 일치한다
- 경유지 0개면 SVG 대신 안내 문구를 낸다

### `functions/test/functions/expenses.test.js` (추가)

- `setExpenseWaypoint`가 `isWaypoint`를 설정·해제한다
- **남이 입력한 경비에도 성공한다** (`updateExpense`와의 차이를 고정)
- **확정된 경비에도 성공한다**
- **완료된 여행에서도 성공한다**
- 없는 `expenseId`는 `EXPENSE_NOT_FOUND`
- 다른 여행의 세션은 `FORBIDDEN`
- 세션 없으면 `UNAUTHENTICATED`
- `addExpense`가 `isWaypoint: false`로 문서를 만든다

렌더링 결과의 시각적 배치(곡선 모양, 겹침, 라벨 가독성)는 단위 테스트 대상이 아니다. 에뮬레이터에서 육안 확인한다.

## 6. 리스크

| 리스크 | 대응 |
|---|---|
| 장소가 많아 SVG가 세로로 매우 길어짐 | 행이 아래로 늘고 페이지가 스크롤된다. 상한을 두지 않는 것이 잘리는 것보다 낫다 |
| 라벨이 14자에서 잘려 어느 장소인지 모름 | `<title>` 툴팁(데스크탑) + 일정 탭에 전체 이름. 터치에서는 잘린 채로 남는다 — 감수 |
| 경유지 토글이 확정된 경비를 건드린다는 인상 | 토글은 `isWaypoint` 한 필드만 바꾼다. 금액·카테고리·제외 인원은 그대로다 |
| 사용자가 경비를 경유지로 표시하는 기능을 발견 못 함 | 빈 상태 안내(§2.8)가 두 경로를 모두 알려준다 |
| 같은 장소를 다른 이름으로 적어 노드가 갈라짐 (`제주공항` / `제주국제공항`) | 정규화하지 않는다. 자동 병합은 서로 다른 장소를 잘못 합칠 위험이 더 크다 |
| `sw.js` `CACHE_NAME` 범프 누락 | 파일 표(§4)에 명시 |
