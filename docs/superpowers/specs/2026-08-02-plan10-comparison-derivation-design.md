# Plan 10 — 카테고리 비교 산출 근거 모달 + 표 읽는 법

날짜: 2026-08-02

## 배경

Plan 9에서 카테고리 비교 표(`이번` / `그룹평균` / `편차` / `여행 전체`)를 냈지만, 숫자만 있고 그 숫자가 무엇을 뜻하는지도 어떻게 나왔는지도 화면에 없다. 실사용에서 다음 질문이 그대로 남았다.

- `이번 118,795원`은 무엇을 나눈 값인가
- `여행 전체 +207,796원`은 무슨 의미로 받아들여야 하는가
- 표시값으로 손계산하면 `69,265 × 3 = 207,795`인데 화면은 `207,796`이다 — 왜 1원이 다른가
- `놀이`·`기타` 행의 `—`는 데이터가 없다는 뜻인가 버그인가

## 목표

- 표의 행을 누르면 그 카테고리의 산출 과정을 보여준다. 누른 셀에 해당하는 줄을 강조한다.
- 표 아래에 컬럼 정의와 해석을 접이식으로 제공한다.
- 비교 대상 여행 수를 표 라벨에 노출한다.

## 비목표

- **백엔드는 변경하지 않는다.** 필요한 값이 이미 `getReportData` 응답에 전부 있다(아래 §3).
- `그룹평균`의 여행별 원본 내역(예: `영월 990,600 ÷ 10명 ÷ 2일`)은 보여주지 않는다. 페이로드에 없고, 이를 위해 백엔드 필드를 추가하는 것은 지금 얻는 값에 비해 과하다. 모달은 결과값과 비교 여행 수까지만 말한다.
- 도넛 차트는 건드리지 않는다.
- `perCategoryCounts` 분모 문제(그 카테고리에 지출이 있었던 과거 여행 수로만 나눔)는 이번 범위 밖이다. 해석의 문제이며 별도 논의가 필요하다.

## 1. 상호작용

### 1.1 왜 행 클릭인가 (셀 클릭이 아니라)

네 숫자는 독립적이지 않다. `편차`와 `여행 전체`는 둘 다 `이번 − 그룹평균`이라는 같은 뺄셈에서 파생된다. 셀마다 별도 모달을 띄우면 `편차` 모달에서도 `여행 전체` 모달에서도 앞의 두 값을 다시 보여줘야 하고, 사용자는 한 카테고리를 이해하려고 모달을 서너 번 여닫으며 머릿속에서 이어붙여야 한다.

터치 크기도 걸린다. 375px에서 실측한 행 높이는 37px이고 행 전체 폭은 약 340px다. 셀 하나는 약 55×37px이며 옆 셀이 바로 붙어 있어 오탭이 쉽다. 권장 터치 타깃 44px에도 못 미친다.

어포던스도 문제다. 셀마다 누를 수 있다는 표시를 넣으면 6행 × 4셀 = 24개의 시각 신호가 편집 디자인 톤의 표에 깔린다.

**채택: 행 전체가 클릭 대상이고, 모달은 하나다. 누른 셀에 해당하는 줄을 강조해 정밀함을 유지한다.** 오탭해도 원하는 정보가 같은 화면에 있으므로 실수 비용이 0이다.

이 앱에는 이미 최종 정산에서 카드를 누르면 계산 내역이 뜨는 관용구가 있다(`settle-card` → `renderSettlementDetail`). 같은 idiom을 확장하는 것이므로 사용자가 새로 배울 것이 없다.

### 1.2 강조 대상 판별

`<tr>`에 `data-category`, 금액 셀 4개에 각각 `data-field="current|group|cmp|delta"`를 단다. 클릭 핸들러가 `e.target.closest('[data-field]')`로 누른 셀을 찾아 `focus`로 넘긴다. 카테고리 이름 셀에는 `data-field`가 없으므로 그 자리를 누르면 강조 없이 열린다.

`focus` 값과 강조되는 줄의 대응은 다음과 같다.

| `data-field` | 강조되는 줄 |
|---|---|
| `current` | 이번 |
| `group` | 그룹평균 |
| `cmp` | 편차 |
| `delta` | 여행 전체 |
| (없음) | 강조 없음 |

`차이` 줄은 어느 셀에도 대응하지 않으므로 강조 대상이 아니다.

## 2. 모달 내용

### 2.1 비교 기준이 있는 행

```
식비 산출 근거

이번        2,494,700원 ÷ 7명 ÷ 3일  =  118,795.24원/일
그룹평균                                 49,530원/일
            (과거 완료 여행 1개의 하루 비율 평균)
─────────────────────────────────────────
차이                                     69,265.24원/일
편차        69,265.24 ÷ 49,530        =  +140%
여행 전체   69,265.24 × 3일           =  +207,796원

평소 페이스로 3일이면 1인당 148,590원이었을 식비가
이번엔 356,386원 들었습니다.

표의 숫자는 원 단위로 반올림해 표시합니다.
```

**소수점은 모달 안에서만 노출한다.** 표는 정수를 유지한다. 표시값으로 손계산하면 `69,265 × 3 = 207,795`인데 앱은 `207,796`을 낸다 — 앱이 반올림 전 값으로 곱한 뒤 마지막에 한 번만 반올림하기 때문이다. 모달이 반올림 전 값을 그대로 쓰면 사슬이 자체적으로 검산되고, 이 1원 차이가 영구히 해소된다.

소수 표기는 **하루 1인 값(`이번`, `그룹평균`, `차이`)에만** 적용한다. 최대 2자리이고 뒤따르는 0은 제거한다(`49,530.00` → `49,530`). 카테고리 총액(`2,494,700원`), 인원, 일수, 편차 %, `여행 전체` 결과값은 모두 정수로 표기한다 — `여행 전체`는 반올림 전 값으로 곱한 뒤 마지막에 한 번만 반올림한 정수다.

`차이` 줄을 별도로 두는 이유는 `편차`와 `여행 전체`가 같은 값에서 갈라진다는 사실을 눈으로 보여주기 위해서다. 이것이 셀별 모달을 택하지 않은 이유이기도 하다.

### 2.2 비교 기준이 없는 행

```
놀이 산출 근거

이번        210,000원 ÷ 7명 ÷ 3일  =  10,000원/일
그룹평균    —

과거 완료 여행에 '놀이' 지출이 없어 비교 기준이 없습니다.
```

`—`가 데이터 누락이나 버그가 아니라는 것을 말해준다. 표에서는 이 설명을 붙일 자리가 없었다.

### 2.3 해석 문구

`여행 전체` 값의 의미를 그 행의 실제 값으로 생성한다.

```
평소 페이스로 {일수}일이면 1인당 {그룹평균 × 일수}원이었을 {카테고리}가
이번엔 {이번 × 일수}원 들었습니다.
```

고정 예시 숫자를 문구에 박지 않는다. 데이터가 바뀌면 설명이 거짓말이 된다.

## 3. 데이터 출처 — 백엔드 변경이 필요 없는 이유

| 값 | 출처 | 근거 |
|---|---|---|
| 분자 (카테고리 총액) | `settlement.categoryTotals[category]` | `computeSettlement`이 확정 지출만 카테고리별로 합산한 값. 도넛이 이미 소비 중 |
| 분모 (인원) | `settlement.perMember.filter((m) => m.due > 0).length` | 백엔드 `perPersonCategoryAverage`의 `memberHasDue`와 동치 |
| 여행 일수 | `tripDays` | Plan 9에서 추가됨 |
| 비교 여행 수 | `tripsInComparison` | Plan 9에서 추가됨 |
| 하루 1인 값 | `currentCategoryPerDay` / `groupCategoryPerDayAverages` | Plan 9에서 추가됨. 반올림 전 값 |

`memberHasDue`와 `due > 0`이 동치인 근거: 두 값 모두 같은 `allocateInteger` 배분 결과에서 나온다. `perPersonCategoryAverage`는 어떤 확정 지출에서든 배분액이 0보다 큰 구성원을 `memberHasDue`에 넣고, `computeSettlement`의 `due`는 같은 배분액을 전부 합한 값이다. 어딘가에서 0보다 큰 배분을 받았다면 합도 0보다 크고, 합이 0보다 크면 어딘가에서 0보다 큰 배분을 받았다. 가중치 0인 구성원은 양쪽 모두에서 제외된다.

**따라서 모달의 산식은 프론트가 독자적으로 재계산한 값이 아니라 서버가 이미 계산해 보낸 값이며, 표의 숫자와 어긋날 수 없다.**

## 4. 표 아래 접이식 설명

`<details>`/`<summary>` 네이티브 요소를 쓴다. JS가 필요 없고, 모바일에서 탭으로 열리며, 접힌 상태가 기본이라 문서형 레이아웃을 해치지 않는다.

`title` 속성이나 hover 팝오버는 쓰지 않는다. 터치 환경에서 아예 뜨지 않는다.

담을 내용:

- **이번** — 이 여행에서 이 카테고리에 1인이 하루 평균 얼마나 부담했는지. 확정된 지출만 집계한다.
- **그룹평균** — 같은 그룹의 완료된 과거 여행들에서 같은 값을 구해 평균낸 값. 총액을 합쳐 총일수로 나눈 것이 아니라 여행별 하루 비율의 평균이라, 여행 길이가 달라도 긴 여행이 평균을 끌고 가지 않는다.
- **편차** — 두 값의 차이를 비율로. 씀씀이가 평소와 얼마나 다른지.
- **여행 전체** — 평소 페이스로 이번 여행 길이만큼 갔다면 나왔을 금액과의 차액. 1인 기준. 카테고리끼리 더할 수 있다.
- **주의 1** — 1인 평균의 분모는 여행 전체 분담 인원이다. 특정 카테고리에서 제외된 구성원이 있어도 같은 분모를 쓰므로, 제외가 걸린 카테고리는 실제 참여자 부담보다 낮게 보인다.
- **주의 2** — 정산 금액과는 다른 수치다. 정산은 가중치대로 나누고 이 지표는 인원수로 균등하게 나눈다. 가중치가 전원 같으면 일치한다.

## 5. 라벨과 어포던스

표 상단 라벨에 비교 대상 수를 붙인다.

```
카테고리 비교 · 하루 · 1인 기준 · 과거 여행 1개와 비교
```

비교군이 하나뿐일 때 "그룹 평균"이라는 표현이 주는 과한 신뢰를 바로잡는다. `tripsInComparison`이 이미 있으므로 값 삽입만 하면 된다.

행이 눌린다는 안내는 최종 정산 섹션이 쓰는 `.muted` 문구 방식을 따른다. 행에는 `cursor: pointer`와 hover 배경을 준다.

## 7. 테스트

`public/test/charts.test.js`에 추가한다.

- `renderComparisonDetail`이 분자·분모·일수를 산식 형태로 내보낸다
- 편차와 여행 전체가 반올림 전 값으로 계산되어 표 값과 일치한다 (표시값 손계산과 1원 어긋나는 케이스를 포함해 검증)
- 소수 2자리까지 표기하고 뒤따르는 0을 제거한다
- 그룹 기준이 없는 카테고리는 `—`와 안내 문구를 낸다
- `focus`로 지정한 줄에만 강조 클래스가 붙고, `focus`가 없으면 아무 줄에도 붙지 않는다
- 카테고리명이 이스케이프된다
- `renderCategoryComparison`이 각 행에 `data-category`를, 금액 셀 4개에 `data-field`를 단다
- 라벨에 비교 여행 수가 들어간다

`<details>` 동작과 hover는 CSS/네이티브 요소이므로 단위 테스트 대상이 아니다. 구현 후 브라우저에서 육안 확인한다.
